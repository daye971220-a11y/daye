# 다예 발행본 재검토와 여행 글 작성 우선 기준

2026-10-06 사용자 요청. 최근 함께 작성한 5편의 발행 본문 전체와 사진·표·스티커 순서를 읽고, 저장된 초안/기준 예시와 비교했다. 블로그 전체 412편을 전수 조사한 것은 아니다. 이번 작업은 읽기와 기준 저장이며 네이버 글은 수정하거나 발행하지 않았다. 원고 원문·사진은 이 문서에 보관하지 않는다.

## 다음 원고에서 실제로 할 일

2026-10-07 추가: 여행 글은 1,000자 이하로 작성하지 않는다. 제목·태그·사진 출처/캡션·표를 제외한 본문을 공백 제외로 측정해 1,000자 초과를 확인한다. 분량 외에도 분석 블로그의 구체적 장면·선택 이유·이동 흐름·사진과 설명 연결과 비교해 수정한다. 반복 조언이나 숫자 재열거로 채우지 않는다. 인물 생성 이미지의 최신 사용자 사진·아이폰 질감 기준은 `travel-blog-delivery-standard.md`를 따른다.

2026-10-07 추가 우선 기준: 제목에 넣은 핵심 질문·장소·가격·혜택·일정·체험과 본문을 반드시 대조한다. 본문에서 확인된 사실로 충분히 답하지 못하면 제목을 수정하거나 검증한 내용을 보완한다. 제목만 강하게 만들거나 미확인 정보로 본문을 채우지 않는다. 원고·사진·썸네일의 별도 보관 및 GitHub 저장은 해당 자료에 대한 사용자 명시 요청이 있을 때만 하며 기본 저장 대상은 지침뿐이다. 네이버 임시저장 요청을 별도 원고 보관 허가로 확대하지 않는다.

1. 장르와 독자 질문을 먼저 정한다. 핵심 매력 1~2개, 방문 판단에 필요한 답, 확인된 불편을 뽑는다. 축제는 먹거리·체험·공연 가운데 무엇이 갈 이유인지, 여행지는 어떤 풍경·동선이 다른지, CPA는 어느 구성·가격이 누구에게 이득인지 먼저 잡는다.
2. 도입은 그 장소만의 구체적인 장면이나 선택 고민으로 짧게 연다. 장소 이름을 다른 곳으로 바꿔도 통하는 ‘눈여겨볼 만해요’, ‘여유를 두면 좋겠어요’, ‘사진 욕심이 나네요’는 자동 삭제 대상으로 본다. 같은 도입·결론을 여러 글에 복제하지 않는다.
3. 경험담의 흐름을 만들되 체험 사실은 제공된 것만 쓴다. 실제 경험이 있으면 도착·행동·기대한 점·불편·반응을 연결한다. 없으면 검증한 풍경·동선·운영과 짧은 선택 판단으로 자연스럽게 쓴다. 재방문·피로·맛·동행자는 만들지 않는다. ‘저라면’으로 모든 절을 대신하지 않는다.
4. 개화는 게시일이 아닌 실제 방문·촬영 날짜와 그때 보이는 구역·꽃 상태를 확인해 짧게 쓴다. 타인의 방문을 내 방문으로 바꾸지 않는다. 날짜·상태를 못 확인하면 그 항목을 빼고 다른 확인된 매력을 보강한다. ‘확인하지 못했어요’, ‘절정이 정해지지 않았어요’, ‘최신 글을 살펴봤는데’와 내부 분석 과정을 공개 원고에 넣지 않는다.
5. 1~2문장, 화면 2~3줄 정도를 의미 단위로 묶고 빈 문단으로 다음 생각과 구별한다. 문장을 단어마다 자르거나 모든 줄을 같은 길이로 맞추지 않는다. 번호+짧은 명사 소주제 바로 아래 관련 사진, 이후 짧은 설명·정보·장면 순으로 읽게 한다. 긴 절은 새로운 내용을 보여주는 추가 사진이나 문맥에 맞는 스티커로 끊는다.
6. 표는 요금·거리/시간·공연 일정처럼 비교가 필요한 곳에 작게 넣는다. 표 아래에는 독자가 선택할 때 필요한 의미만 말한다. 모든 숫자를 문장으로 다시 읽어주지 않는다. 근거 없이 실제 대기·혼잡·시간을 확정하지 않는다.
7. 감정 괄호는 한 글 2~3개, ㅎㅎ·ㅠㅠ·…는 장면에 맞을 때 쓴다. ‘하..’ 같은 속마음의 호흡은 참고하되 빈 감탄이나 매 절의 괄호가 아니라 구체적인 이유 뒤의 솔직한 반응이어야 한다. 추천과 아쉬움 모두 확인된 내용·제공된 경험에 붙인다.
8. 사진은 설명을 대신 반복한 글자 카드가 아니라 장면·옵션·정보를 보여주는 역할을 갖게 한다. 실제 안내가 필요한 주차·노선은 공식 안내·지도·표를 먼저 쓴다. 분위기 AI 사진 때문에 본문에 장황한 면책 설명이 필요해지면 적합한 이미지로 교체한다. 생성 사진은 자연스러운 휴대폰 질감과 간단한 AI 표시, 개화·시설 실제 증거로 사용 금지. 썸네일은 본문과 다른 배경을 별도 파일로 기본 전달하고 후킹 문구도 따로 추천한다.
9. 서식은 16px 나눔바른고딕 가운데, 19px 번호 선 인용구, 핵심만 볼드·색이라는 다예 선호를 따른다. 스티커의 표정·동작·위치는 장면별로 정하고 앞뒤 글과 기계적으로 일치시키지 않는다. 글의 질을 서식 개수로 평가하지 않는다.
10. 저장 전 각 문장을 ‘새 정보 / 장면 / 선택 이유 / 필요한 반응’으로 점검한다. 해당하지 않는 문장, 중복 조언·표 재설명·미확인 항목은 지운다. 축제·여행은 실제 방문 도움과 솔직한 추천, CPA는 검증한 이득과 자연스러운 예약 행동으로 마무리한다. 요청받은 경우 사진·서식을 적용하고 임시저장까지 확인한다.

이 문서와 최신 제공 기준을 다음 작성 전에 읽는다. 기억의 수단은 프로젝트 파일이며 현재 발행본을 자동으로 좋은 원고의 모범으로 삼지 않는다.
