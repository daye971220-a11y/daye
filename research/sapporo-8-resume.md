# 삿포로 여행 원고 8편 집에서 이어하기

2026년 10월 20일 기준. 원고 8편은 아직 작성하거나 네이버에 임시저장하지 않았다. 사진 분류와 전달 ZIP은 준비됐다. 사용자가 최신 참고 글 본문을 직접 전달하기로 선택했으며, 아직 본문이 도착하지 않았다. 원고를 이미 저장한 것으로 오해해 수정하거나 중복 생성하지 않는다.

사용자가 기존 구글드라이브 폴더 저장을 승인했고, `삿포로8편-사진61장.zip` 업로드 완료 100%와 폴더 내 파일을 확인했다. ZIP 크기는 37,140,155바이트이며 로컬 압축 무결성·사진 61장·번호표 8개·CSV 포함을 검증했다. 사진 ZIP과 업로드 증빙 화면은 Git에 넣지 않는다.

## 집에서 시작할 순서

1. daye 프로젝트를 `git pull --ff-only`로 최신화하고 `AGENTS.md`, 이 문서, `daye-blog-writing-review.md`, `travel-blog-delivery-standard.md`를 읽는다. 작성일에 다예 발행본과 지정 블로그의 해당 장르 기준을 대조한다.
2. 사용자가 공유한 구글드라이브 삿포로 폴더에서 `삿포로8편-사진61장.zip`을 받는다. 사진과 개인 드라이브 링크는 공개 GitHub에 올리지 않는다. 새 대화에 링크가 없으면 사용자에게 폴더 링크만 다시 받는다. 기존 675개 사진·영상 전체를 다시 다운로드하지 않는다.
3. ZIP을 풀어 `사진번호표-미리보기.html`, `사진별-삽입위치.csv`, 8개 번호표 JPG를 읽는다. 폴더별 번호와 원본 파일명을 유지한다. 현재 삽입 위치는 원고 작성 전 배치안이므로 원고와 최종 대조한다.
4. 사용자가 전달할 최신 참고 글 본문을 확인한다. 기존 분석으로 대신 진행해도 되는지 물었을 때 사용자는 **최신 참고 글 본문을 직접 전달**하는 쪽을 선택했다. 본문을 받은 것으로 간주하거나 제목·요약만으로 원문 대조 완료라고 하지 않는다. 각 주제 관련 글 최소 두 편과 공식 최신 조건을 대조한다.
5. 최신 네이버 발행글과 임시저장 제목을 다시 확인한 뒤 1번 비에이부터 8번 삿포로 시내까지 작성한다. 사진 번호를 본문에 표시하고 글만 명시적으로 임시저장한 뒤 같은 저장본을 다시 열어 검수한다. 발행과 사진 업로드는 하지 않는다.

## 조사 범위와 중복 확인

분석 대상은 사진·이미지 637개와 MOV 38개, 총 675개였다. 최초 50개 안내는 처음 표시된 목록만 본 오류였고 정정했다. 사진 미리보기 전체와 필요한 확대 사진을 대조했으며 영상은 대표 장면과 일부 재생 확인이다. 38개 영상 전체 시청 완료로 보고하지 않는다.

네이버 임시저장 목록 72개의 제목을 확인했다. 이번 8편과 동일 제목은 없었으나 `북해도 온천 패키지 3박4일 도야·오타루·비에이, 5% 할인 99만원대`가 있어 새 장소별 원고와 목적·상품을 구분해야 한다. 발행글 전체의 중복 확인까지 마친 것은 아니다. 이번 작업으로 네이버 원고를 새로 저장하거나 발행하지 않았다.

비에이신사, 아사히카와 가미카와신사, 삿포로 홋카이도신궁은 서로 다른 장소다. 스키장은 키로로나 테이네로 임의 변경하지 않는다. 오타루 그란벨·토리피토 예약 자료는 있지만 객실 사진 대응이 확정되지 않아 이번 8편에 숙소 후기 두 편을 추가하지 않았다. 이름을 모르는 사진은 사용자에게 실제 이미지를 보여주며 확인하고 파일명만 제시해 기억을 요구하지 않는다.

## 문체와 저장 기준

지정 블로거의 구조·말투와 다예 직접 교정을 우선한다. 일반적인 추천을 반복하지 말고 장소 고유 장면과 실제 선택 이유를 쓴다. ㅎㅎ·ㅠㅠ·…만 붙여 사람다운 문체로 취급하지 않는다. 사용자 사진이 있다고 맛·만족·동행 반응·예약 상품을 만들어 쓰지 않는다. 모르는 할인·혜택·객실 조건은 허용된 구체적 대괄호 보충칸으로 남긴다.

평균 약 2,000자는 참고 목표이며 공백 제외 본문 1,000자 초과, 짧은 의미 단위와 충분한 설명을 함께 지킨다. 제목·태그·사진 캡션·표·예약 문구는 본문 계수에서 제외한다. 마지막에 실제 주제에 맞는 해시태그를 넣는다. 사진은 사용자가 직접 올리고, 글에는 번호와 위치를 표시한다. 네이버 실제 본문에서 소제목·색 강조·굵기·줄바꿈·표·링크·잔여 문자를 검수한다.

최신 참고 본문 접근 시 브라우저 보안 정책 차단이 발생했다. 다른 호스트·브라우저·우회 명령으로 차단된 본문을 가져오지 않는다. 사용자가 전달할 원문을 기다리는 상태를 유지한다. 새 환경의 정상 접근 여부와 원문 확보 여부는 실제 확인하며 과거 제한을 로그인 문제로 꾸미지 않는다.

이번 집에서 이어하기 요청으로 진행 기록·작성 지침을 동기화한다. 사진은 사용자 승인에 따라 기존 구글드라이브 폴더에 전달하고 공개 GitHub에는 넣지 않는다. 로컬 임시 검토 폴더·다운로드 경로·로그인 정보·예약 PIN·개인 파일 링크를 공개 문서에 복제하지 않는다. 원고 전문은 아직 존재하지 않으며 이후 원고의 Git 보관은 별도 요청 때만 한다.
