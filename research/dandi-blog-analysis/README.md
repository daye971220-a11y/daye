밍짱이 분석과 같은 범위로 숙소·맛집·축제 글 3개를 선정해 본문 끝까지 읽고, PC 화면의 구성 요소 172개를 기록했다. 스티커, 이모지, 글씨체, 크기, 색, 볼드, 밑줄, 기울임, 배경, 줄 간격, 사진 조합, 영상, 표, 지도, 링크, 구분선과 마무리까지 포함했다. 요소별 전체 목록은 [inventory.md](inventory.md), 측정값은 각 `*-measurements.json`, 집계는 `summary.json`이다.

이 분석은 세 표본의 관찰이다. 프로필의 ‘상위 0.1%’는 작성자의 소개이며 독립 검증한 순위가 아니다. 조회수·검색 순위·전환율·수익·모바일 화면은 검증하지 않았다. 확인용 화면은 로컬에만 보관하며 GitHub에는 분석·측정값만 저장한다.

## 2. 제목을 만드는 방식

- 숙소: 지역 + 숙소명 + 주요 시설 + 객실 특성 + 여행 대상 + 추천. 수영장·스파·35평·취사·가족여행처럼 실제 선택 조건을 한 제목에 모은다.
- 맛집: 대기·재방문에 대한 경험의 결론을 앞세운 다음 지역·거리·맛집·상호를 붙인다. 검색 대상과 읽고 싶은 이유를 함께 만든다.
- 축제: 관심을 끄는 짧은 표현 + 행사명·연도 + 일정·먹거리·체험·주차·가볼만한곳. 첫 문구로 호기심을 만들고 뒤에 방문 정보 항목을 모은다.
- 숙소·축제는 본문 앞에서 제목을 한 번 더 반복한다. 맛집 표본은 고지 배너 다음 경험 이야기로 바로 들어간다.
- 이 구성의 검색 노출 효과는 조사하지 않았다. 관심을 끄는 문구를 쓰더라도 실제 사실과 다른 인파·흥행을 만들어 넣지 않는다.

## 3. 글 유형에 따른 전개

### 숙소 후기

대가족 여행에서 숙소를 고르기 어려웠던 상황 → 선택 이유 → 위치·연락처·지도 → 실제 이동과 체크인 → 객실 유형·인원·비교 가격 → 방·욕실·주방의 현장 설명 → 부대시설 → 수영장·스파의 비용과 사용 경험 → 조식·편의시설 → 할인 안내 → 가족에게 맞았던 이유 → 관련 숙소 글 3개 → 태그.

특히 이용 순서와 사진 순서가 가깝다. 위치가 예상보다 시내와 멀었던 점, 준비해야 하는 물품, 시설 관리와 수영장 규모 등 아쉬운 조건을 장점 사이에 넣는다. 조식은 직접 이용하지 않았다고 밝히고 안내 정보를 소개한다. 모든 시설을 이용한 것처럼 서술하지 않는다.

### 맛집 후기

경주에서 다시 찾아간 계기 → 인기와 대기 경험 → 주소·운영시간·주차·예약·동반 조건 → 지도 → 공간 분위기 → 메뉴판 → 주문한 메인과 가격 → 음식의 향·식감·맵기 → 밥과 곁들이는 메뉴 → 대기·예약·주차 조언 → 재방문 이유 정리 → 관련 지역 숙소 글 2개 → 태그.

외관·공간·메뉴·음식·밑반찬 사진을 따라 읽게 한다. 메뉴를 나열하는 데서 끝내지 않고 서로 곁들였을 때의 맛과 아이가 먹을 수 있는 대안을 설명한다. 가격표를 새로 만든 대신 메뉴판 사진과 본문 가격 정보를 사용한다.

### 축제 정보 글

제주 여행에서 색다른 먹거리 축제를 찾는 사람에게 제안 → 행사 포스터와 지도 → 기간·개막식·장소·주소 요약 → 먹거리 → 맨손잡기 → 어린이 체험 → 참여 이벤트 → 첫날 공연 → 주차 → 작성자가 선택할 가상 방문 순서 → 추천 대상 정리 → 관련 제주 숙소 글 2개 → 마무리 이미지와 태그.

실제 방문 후기가 아니라 앞으로 열리는 행사의 정보와 방문 제안이다. 출연 가수 이름이 일정표에 없다는 한계를 밝힌다. 주차 혼잡은 확정 사실과 구분해 가능성으로 서술한다. 동선을 제안하는 마지막 절은 방문 경험처럼 바꾸어 쓰면 안 된다.

세 글에 고정된 5항목 목차는 없다. 정보 요약 인용구와 주제별 소제목이 목차 역할을 대신한다.

글자 크기를 13px로 줄이면서 줄 높이는 27.3px로 넉넉하게 둔다. 짧은 줄 몇 개와 빈 문단으로 작은 글씨의 밀도를 낮춘다. PC 본문 영역은 약 966px다. 본문 제목의 녹색은 실제 표시 값이며 작성자가 제목에서 직접 지정한 색과 테마 상속을 구분해야 한다.

일반 텍스트의 공백 제외 문단 길이 중앙값은 맛집 11자, 숙소 16자, 축제 11자다. 태그는 제외했다. 맛집은 220문단 중 빈 문단 96개, 숙소는 371개 중 211개, 축제는 165개 중 58개다. 사진 전후의 빈 문단도 포함한 수치라 순수 글자 사이 여백만 뜻하지 않는다.

요소 바깥 위 여백은 주로 20·30·40px이며 숙소에는 5px 간격도 있다. 빈 문단과 인용구 내부 여백이 추가돼 사진 사이가 상당히 넓어지는 구간이 있다. 글씨만 따라 읽기보다 사진 → 설명 → 다음 사진으로 이동하는 리듬이다.

## 6. 볼드·밑줄·기울임·취소선

일반 텍스트의 글자 기준 볼드 비중은 맛집 0%, 숙소 약 1.0%, 축제 약 13.7%다. 빈 문자·공백·파란 태그를 제외했으며 인용구 제목과 표의 볼드는 이 비중에 넣지 않았다. 밍짱이와 비교할 때도 본문 텍스트 기준으로 비교한다.

- 맛집: 일반 본문에 볼드·직접 밑줄·이모지·형광펜 없이, 6개 절 제목의 명조체 기울임과 사진으로 구분한다. 상단 위치 요약 인용구에는 굵은 제목과 항목이 있다.
- 숙소: 일반 후기 문장은 대부분 보통 굵기. 저렴한 가격을 설명하는 문장 3구간에 직접 밑줄, 할인 조건 2구간에는 볼드와 밑줄을 함께 쓴다. 직접 밑줄 총 5구간, 링크 밑줄 2구간이다. 소제목·정보 요약에는 볼드를 더 사용하지만 기울임은 확인되지 않았다.
- 축제: 행사명·주요 체험·참여 프로그램·공연 시간·추천 동선을 볼드로 구별한다. 7개 절 제목은 기울임이고 직접 밑줄은 없다.
- 취소선은 세 글 모두 관찰되지 않았다. 본문의 기울임과 소제목 양식의 기울임을 구분한다.

## 8. 이모지·기호·말투

- 맛집: 작성자가 넣은 이모지 0개.
- 숙소: 컬러 이모지 없이 가격 확인 링크 양쪽에 삼각형 기호 ▶와 ◀가 각 1개. 유니코드 그림 기호로 분류될 수 있지만 여행 감정 이모지와 구분해 기록한다.
- 축제: 마지막 추천 문장에 🐟와 🌊 각 1개, 총 2개.
- `ㅠ`, `ㅎㅎ`, `ㅋㅋ`, `:)`, 괄호, 물결표, 느낌표 등은 이모지 수에 포함하지 않았다. 경험 반응과 아쉬움을 가볍게 표현한다.
- 맛집·축제의 일부 빈 줄에는 일반 공백 대신 보이지 않는 빈 문자(⠀)를 넣었다. 시각적으로 문단 사이 여백을 유지하는 역할이다.
- 숙소는 설명이 비교적 길고 현장 반응을 섞는다. 맛집은 짧은 문장으로 향·식감·조합을 전개한다. 축제는 안내형 문장에 방문 제안을 더하며 감정 표현을 줄인다.

## 9. 사진·콜라주·영상·지도

맛집은 단일 이미지 12개 중 고지 배너 1개, 사진 11개에 2장짜리 콜라주 2묶음을 더해 사진 15개다. 일부 음식에는 짧은 캡션을 붙이고, 세로 영상 1개를 메인 메뉴 설명 구간에 배치한다. 메뉴판·음식·공간을 직접 보여주는 이미지가 글의 증거 역할을 한다.

숙소는 단일 이미지 29개, 나란히 놓은 사진 7묶음(각 2개), 콜라주 1묶음(4개)으로 이미지 47개다. 같은 시설의 서로 다른 각도나 비품을 묶어서 설명하고, 객실 세로 영상 1개를 가격 설명과 내부 사진 사이에 둔다. 일반 사진은 큰 폭을 쓰며 일부는 본문 최대 폭에 가깝게 배치한다. 2장 병렬 배치에는 약 480.5px씩인 조합과 가로·세로 사진 폭을 다르게 나눈 조합이 함께 있다.

축제는 포스터와 프로그램·일정 이미지로 안내를 보조한다. 그림 일부에는 ‘AI 활용’ 표시가 있고 마무리 이미지 파일 이름에도 AI 생성 흔적이 있지만, 모든 이미지가 생성 이미지라고 단정하지 않는다. 미래 행사의 이미지를 본인의 현장 방문 사진처럼 설명하지 않는다.

네이버 이미지 요소에는 별도 둥근 모서리·테두리 효과가 관찰되지 않았다. 요소 필터는 none, 불투명도는 1이다. 이것은 원본 사진의 보정 여부를 뜻하지 않는다. 작성자는 프로필에서 카메라 촬영·보정을 한다고 소개하지만 장비나 보정 설정은 확인되지 않았다.

## 10. 표·인용구·구분선·링크·태그

- 숙소 가격표는 약 328px 폭의 작은 가운데 표다. 3열·5행이며 머리행 연회색, 3개 비교 옵션, 마지막 3열 병합의 노란 가격 링크 행으로 구성한다. 셀 여백 10px, 점선 회색 격자를 사용한다. 밍짱이의 본문 폭에 가까운 큰 비교표와 다르다.
- 맛집·축제에는 편집기로 만든 표가 없다. 메뉴판·행사 일정은 이미지로 제시한다.
- 인용구는 맛집 7개·숙소 5개·축제 8개다. 상단 정보 요약과 중간 소제목에 서로 다른 크기·굵기·기울임·정렬을 적용한다. 숙소에는 밑줄 장식과 왼쪽 세로선 장식이 섞인다.
- 독립 구분선은 맛집 2개·숙소 1개·축제 3개다. 축제에는 짧은 가운데 선(약 220px), 장식선(약 192px), 본문 폭의 긴 선(약 886px)을 함께 사용한다.
- 관련 글 카드는 모두 끝부분에 모인다. 맛집·축제 2개씩, 숙소 3개. 글 내용과 같은 지역의 숙소 글로 연결한다. 카드 썸네일은 약 450×270px이며 카드의 자동 제목·설명·도메인 색은 작성자의 본문 서식과 구분한다.
- 숙소는 관련 글 카드와 별도로 중간 가격 확인 링크, 뒤쪽 쿠폰 링크가 있다. 맛집·축제는 같은 예약 링크를 도입과 결론에 반복하는 구성이 아니다.
- 직접 쓴 해시태그는 맛집 14개, 숙소 8개, 축제 11개. 맛집은 주로 한 줄 2개씩, 숙소는 두 줄에 나누고, 축제는 한 문단에 이어 쓴다. 네이버 하단 태그 UI는 중복 집계하지 않는다.

## 11. 다예 원고에 적용할 기준

숙소·맛집은 사용자가 제공한 실제 경험과 사진을 중심으로 작성한다. 방문 계기 → 기본 정보 → 실제 동선·선택·감각 → 제한·준비물 → 추천 대상의 흐름이 유용하다. 축제는 행사 공식 정보와 방문 제안으로 작성하고, 실제 경험과 예상·권고를 구분한다.

서식은 차분한 기본색, 짧은 줄, 충분한 여백, 주제를 알리는 소제목을 출발점으로 삼는다. 볼드는 정보형 글의 프로그램명·시간 등에 선택적으로 사용하고, 비용·예약 조건에는 표·밑줄·링크를 사용한다. 스티커와 이모지는 장면에 맞을 때 넣는다. 13px가 모든 기기에서 좋은지는 별도 확인하고 다예의 독자와 화면에 맞춰 조정한다.

다예가 원고를 요청하면 새 문장과 함께 `[명조체 소제목/기울임]`, `[볼드]`, `[직접 밑줄]`, `[가격표]`, `[사진 2장 병렬]`, `[영상]`, `[스티커 역할]`, `[관련 글 카드]`처럼 적용 위치를 안내한다. 실제 가격·기간·쿠폰·시설 조건은 원고 작성 시 공식 자료로 다시 확인한다.

두 블로그의 공통점과 차이는 [비교 가이드](../travel-blog-common-patterns.md)를 참고한다. 단디쓰의 고유 문장·캐릭터·사진을 그대로 복사하는 대신 정보 구성과 편집 원리를 다예의 경험과 문체로 적용한다.
