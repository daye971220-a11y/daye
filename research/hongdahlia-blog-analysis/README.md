## 2. 제목·도입·전개 방식

제목은 지역/숙소명 + 관심 시설·객실 + 가격 비교·할인·예약·후기 항목을 이어 붙인다. 맛집은 지역·동네·상호·주문 메뉴·예약·주차를 모은다. 제목에 들어간 궁금증을 본문의 번호 소제목으로 다시 풀어준다. 별도의 목차 표는 없다.

경주 힐튼: 가격이 예상보다 괜찮았다는 발견 → 성인 2명 룸온리·조식 패키지 비교 예고 → 위치·이용 정보 → 플랫폼별 가격 → 쿠폰·결제 할인 → 조식 패키지 차액 → 뷔페 → 계절별 수영장 선택 → 관광형/조식형 추천 → 예약 정보 → 위치 정보.

후쿠오카: 실제 모녀 숙박 경험과 결론을 먼저 제시 → 위치의 장단점 → 실제 이용한 Chapter 1과 현재 비교 중인 Chapter 2 → 환불 가능한 가격 비교 → 쿠폰 적용 → 조식 선택 → 상위 객실 라운지 비용 → 대욕장 부재 → 추천 대상 → 예약·위치 정보.

안민: 친구와 방문·예약한 경험 → 도착 시각과 대기 팀 수 → 기본 정보 요약 → 위치·주차 → 주문 메뉴와 방문 시점 가격 → 직원이 구워주는 서비스 → 선호 부위·식감·먹는 조합 → 껍데기 항정살 → 모임에 적합한 이유와 예약 조언 → 위치 지도.

공통적으로 질문 → 확인한 정보/경험 → 독자에게 미치는 의미 → 조건별 선택 조언으로 이어진다. 숙소의 예약 링크는 해당 절에서 해결한 질문에 맞춰 이름을 바꿔 반복한다. 맛집은 실제 방문 순서와 사진 중심이며 숙소용 가격·쿠폰 구조를 억지로 넣지 않는다.

## 3. 실제 경험과 현재 조사를 연결하는 방식

후쿠오카 글의 좋은 구분은 ‘예전에 Chapter 1에 묵었다’와 ‘지금 예약한다면 Chapter 2를 볼 것 같다’를 따로 쓰는 것이다. 넓이·캐리어 동선은 실제 이용 경험, 현재 가격·상위 객실 선택은 조사와 의견이다. 라운지 포함 객실을 소개하더라도 해당 객실을 이용한 경험으로 바꾸지 않는다.

경주 글에는 ‘실제로 예약한다면’이라는 조사형 표현과 부모님이 좋아한 조식 경험이 섞인다. 현재 가격으로 실제 예약·숙박했다는 뜻은 아니다. 뷔페·수영장 안내도 운영 정보와 방문 경험의 시점을 분리해 읽어야 한다.

맛집은 동행자·시각·대기 팀 수·주문 메뉴·가격·직원의 행동·개인적으로 좋아한 부위 같은 구체적인 장면으로 경험을 만든다. 편의 시설은 사진과 함께 소개하고, 단순히 맛있다는 말보다 따뜻하게 먹는 방식과 대화하기 편한 이유를 풀어준다.

다예가 보내는 글도 실제 본인 경험, 다른 사람의 후기, 공식 운영 정보, 현재 조사 가격으로 구분해 활용한다. 제3자 경험을 다예의 방문담으로 전환하지 않는다.

## 4. 사진의 역할과 객실·시설 대응

큰 단일 사진과 짧은 설명을 반복한다. 숙소에서는 객실·외관·로비·조식·식당·수영장 이미지로 해당 시설을 보여주고, 할인 절에는 쿠폰 화면을 넣는다. 맛집은 외관·대기 안내·매장·메뉴·접시·굽는 과정·쌈·편의 시설 등 설명의 근거가 되는 사진을 배치한다. 맛집에는 영상 1개도 포함한다.

후쿠오카 객실 설명에서 사진에 연결할 핵심은 캐리어 두 개를 펼치는 공간, 침대를 따로 쓰는 구성, 역과의 거리, 로비 분위기다. 현재 비교 상품인 Chapter 2나 라운지 객실 Episode 6은 실제 이용 객실 Chapter 1과 구분해야 한다. 사진을 자동으로 Chapter 2 사진이라고 붙이면 안 된다.

경주에서는 조식과 디너 메뉴를 구분하고, 야외 수영장 사진이 있어도 현재 계절에 이용할 수 있다는 뜻으로 쓰지 않는다. 운영 종료 시점과 실내 대안을 설명에 연결한다.

사진별 촬영자·공식 출처·사용 허락이 본문에서 모두 확인되는 것은 아니다. 사진을 다예 원고에 제공할 때는 블로그에서 그대로 가져오는 방식 대신 공식/예약 사이트 또는 제공 자료에서 사진 출처와 객실명·전망·시설을 확인한다. 실제 객실 사진과 쿠폰 화면, 링크 카드 썸네일을 구분한다. 실제 객실의 넓이·전망은 사진만으로 확정하지 않고 객실 설명과 대조한다.

이미지 요소의 별도 둥근 모서리·필터는 관찰되지 않았으며 불투명도는 1이다. 원본 사진의 보정 여부는 이 설정으로 판단할 수 없다. 큰 사진에는 약 966px 또는 886px 폭이 관찰되고, 링크 카드 썸네일은 약 450×270px다. 인물·음식·시설의 사진 선택과 편집기 효과를 구분한다.

## 5. 가격 비교의 구조와 확인해야 할 조건

아래 금액은 원문이 제시한 비교 사례이며 2026-10-06 현재의 예약 가능 가격을 별도로 검증한 것이 아니다.

경주 비교는 성인 2명·디럭스 더블 룸온리로 플랫폼 2곳을 나란히 둔다. 본문은 같은 날짜라고 설명하지만 실제 체크인/아웃 날짜를 명시하지 않는다. 비교표는 여기어때 184,000원, 야놀자 200,000원으로 제시하고 낮은 가격만 빨강으로 표시한다. 객실 종류·인원을 맞추려는 구조는 유용하지만 세금·쿠폰 적용 단계·취소 조건까지 맞았는지는 표만으로 확인할 수 없다.

조식은 룸온리 184,000원, 조식 2인 패키지 248,400원, 성인 2인 현장 조식 100,000원으로 비교한다. 핵심 계산은 `184,000 + 100,000 - 248,400 = 35,600원`. 비교 기준이 같다는 전제 아래 계산은 맞다. 표는 패키지 총액과 조식만의 비용을 나란히 두므로 다예 원고에서는 룸온리+조식의 합계 284,000원도 표시하면 더 명확하다.

후쿠오카는 Chapter 2 트윈·환불 가능 조건으로 트립닷컴 216,918원, 여기어때 228,183원, 아고다 233,001원을 제시한다. 환불 불가 197,109원은 표 밖에서 따로 설명한다. 환불 가능한 금액과 불가능한 금액을 같은 순위로 묶지 않는 점을 적용할 수 있다. 다만 실제 날짜·인원·환불 마감·세금·조식 포함 여부는 충분히 명시되지 않았다.

후쿠오카 조식은 엔화 현장 금액과 원화 추가 금액을 설명하지만 정확한 환율·합계 비교표는 없다. 상위 라운지 객실의 가격대는 소개하지만 모든 객실 차액을 같은 날짜로 정밀하게 표로 비교한 것은 아니다.

다예 원고의 비교표에는 체크인/아웃·박수·성인/아이와 나이·객실 수·객실명/침대/전망·조식·취소 마감·세금·추가 요금·쿠폰/결제 할인 적용 단계·통화·확인 시점을 붙인다. 조건이 다른 상품은 별도 표 또는 별도 행으로 분리한다. 매진은 확인한 날짜와 조건에 한정해 적는다. 플랫폼의 ‘최저가 보장’과 실제로 가장 저렴하다는 판단도 구분한다.

## 6. 할인·예약 링크의 흐름

국내 숙소는 플랫폼 가격 비교 → 오픈런·쿠폰 화면 → 회원 쿠폰 → 결제 할인 → 최종 결제 화면에서 확인 → 예약 링크 카드로 이어진다. 할인률을 모두 더해 확정 할인으로 계산하지 않고 중복 적용 여부가 달라질 수 있음을 설명한다.

해외 숙소는 가장 낮았던 기본 가격 → 해당 플랫폼 쿠폰 → 다른 플랫폼 쿠폰 적용가 재비교로 이어진다. 위치·객실·조식 등 각 절의 링크 문구를 독자의 질문에 맞춰 바꾼다. 같은 목적지 URL이라도 문구가 달라 반복이 덜 기계적으로 보인다.

실제 원고에는 사용자가 제공한 예약 사이트와 확인 가능한 링크를 사용한다. 할인 한도·최소 결제액·대상 회원·기간·중복 조건이 확인되지 않으면 임의로 확정하지 않는다. 예약 링크가 있다고 실제 예약이나 결제를 수행하는 것은 아니다.

직접 밑줄은 세 글 모두 0구간이며 밑줄은 링크에 적용된다(경주 8구간, 후쿠오카 10구간, 맛집 0). 기울임·취소선은 세 표본에서 관찰되지 않았다. 밍짱이처럼 본문 핵심 문장마다 노란 형광펜을 반복하지 않는다. 사진 속 메뉴판·광고·쿠폰 색은 수동 본문 색으로 세지 않았다.

총 9개지만 고유 자산은 5개다. 185×160px로 표시되며 원본 자산은 370×320px다. 맛집의 앞뒤 스티커가 정보 블록을 말풍선처럼 감싸는 조합은 감정 스티커와 다른 편집 용도다. 예약·위치 스티커는 다음 요소가 무엇인지 알려주는 표지 역할이다. 공식 스티커 상품 이름은 확인하지 않았다. 숙소의 제휴 고지는 확인했지만 수익과 계약 조건은 알 수 없다.

## 10. 이모지·표·지도·마무리

경주 6개: 🔗×2 ✨×2 👇×2. 후쿠오카 9개: 🔗×3 🔎×2 👇×4. 맛집은 0개. 숙소 이모지는 거의 모두 예약·쿠폰·가격 링크를 가리키는 용도다. 느낌표·물결표·ㅎㅎ·ㅋㅋ·ㅠㅠ·괄호와 `>>`는 이모지로 세지 않았다.

가격표는 모두 약 443px 폭이다. 경주 플랫폼 표는 3행 2열, 조식 표는 2행 3열, 후쿠오카 플랫폼 표는 3행 3열이다. 세로 격자보다 가로선을 중심으로 단정하게 구분한다. 플랫폼명 → 가격 → 예약 링크의 배열을 반복한다.

숙소는 결론 → 예약정보 스티커 → 링크 카드 → 위치정보 스티커 → 지도 순서가 공통이다. 지도에 호텔과 주변 장소를 함께 넣는다. 맛집은 결론 → 위치정보 스티커 → 지도다. 관련 글 카드와 해시태그로 끝내는 단디쓰 방식과 다르다.

## 11. 다예 원고에 적용할 기준

경험은 사용자가 준 자료에 기반하고, 객실·시설 사진은 실제 유형·전망·사용 여부에 맞춰 연결한다. 현재 가격 비교는 같은 조건으로 별도 확인한다. 표를 낸 뒤 독자가 아낄 금액과 선택할 기준을 계산해 설명하고, 그 질문에 맞는 링크로 이어간다.

완성 원고에는 사진 순서·객실명·캡션, 가격 비교표·계산, 소제목·색·볼드·링크·스티커 위치를 지정한다. 새로 검색한 실제 사진은 출처와 사용 가능 범위를 확인해 제안하고, 생성 이미지는 실제 시설 사진으로 제시하지 않는다.

요청된 작업 범위는 [원고·사진·가격 비교 제공 기준](../travel-blog-delivery-standard.md), 다른 블로그와의 비교는 [공통 방식과 차이](../travel-blog-common-patterns.md)에 보존했다.
