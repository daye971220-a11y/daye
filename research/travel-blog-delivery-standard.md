- 공개 본문에 ‘직접 경험하지 않았다’는 조사 과정과 관찰자 표현을 불필요하게 드러내지 않는다. 확인된 서비스·활동은 ‘가이드가 가족사진을 찍어줘요’, ‘이 코스를 돌아요’처럼 행동의 주체와 장면을 직접 설명한다. 이 표현도 실제 제공이 확인된 경우에만 사용한다.

- 저장 전 글 전체를 읽어 설명서 말투·상품 밖의 관찰·반복 추천·모호한 구성/흐름 표현이 누적되는지 별도로 검수한다. 현재 횡성 초안에서도 ‘즐기는 구성이에요’, ‘고르는 재미가 있어요’ 등이 반복돼 교정 대상으로 확인했다. 이 초안을 승인된 문체 예시로 고정하지 않는다. 향후 모든 관련 글에 적용하되 기존 원고 전체의 일괄 수정·삭제로 확대하지 않는다.

- **문체·구성 기준:** 사용자가 이름을 지정해 분석을 요청한 블로거들의 저장 분석과 사용자 직접 교정만 기준으로 삼는다. 관련 장르 분석을 실제로 읽고 도입, 정보 순서, 사진 뒤 설명, 짧은 문단, 구체적인 감정과 마무리에 적용한다. 어드바이저 유입 글은 이 목록을 자동으로 확장하지 않는다. 타인의 고유 문장·개인 경험·사진을 복제하지 않는다.

- 인물 참고 원본은 사용자 미래 참조 요청에 따라 `delivery/personal-image-reference/daye-travel-night.png`, `daye-daily-mirror.png`, `daye-face-reference.png`에 로컬 보관했다. `/delivery/`는 Git 제외 대상이다. 원본 이미지·얼굴 자료는 GitHub에 넣지 않고 지침만 동기화한다. 새 컴퓨터에서 파일이 없으면 다시 첨부받으며 지침만으로 얼굴을 정확히 기억한다고 주장하지 않는다. 생성 이미지는 실제 여행 경험·행사 현장 사진의 증거로 사용하지 않는다.

- 작성·수정 후 제목과 본문을 대조한다. 제목에 약속한 장소·가격·혜택·일정·체험·비교·핵심 질문을 본문에서 확인된 근거로 설명한다. 제목의 검색어를 본문에 한 번 넣는 것만으로 검수를 끝내지 않는다. 본문에서 답하지 못하는 후킹이나 미확인 주장은 제목에서 빼거나 범위를 좁힌다. 필요한 보완은 확인된 사실만 사용한다.
- 원고·본문 사진·썸네일·원고 이력의 별도 보관 및 GitHub 업로드는 사용자가 해당 자료의 보관을 명시적으로 요청할 때만 한다. 기본으로 저장하는 것은 지침과 작성 기준이다. 네이버 직접 작성·임시저장 요청은 해당 편집기에서 마무리하고 별도 원고 파일·보관 폴더·GitHub 사본을 자동 생성하지 않는다. 전달 파일도 요청한 범위에 한해서만 만든다.

## 최우선 적용 — 발행본 재검토 후 작성 방식 교정

사용자는 현재 직접 고친 글도 만족스럽지 않으며, 바나나푸딩·디제이트립·밍짱이·케넨·홍달리·모찌트립·단디쓰 분석을 실제 문장에 적용하길 원한다. [다예 발행본 재검토와 작성 우선 기준](daye-blog-writing-review.md)에 최근 함께 작성한 5편의 확인 결과와 다음 작성 절차를 저장했다. 원고 작성 전에 읽는다. 현재 수정본의 여백·직접적인 감정·표·강조 선호는 유지하되 남아 있는 가정형·미확인 안내·중복 문장을 모범으로 고정하지 않는다.

- 장소만의 장면과 구체적 선택 이유를 먼저 정하고 사진·짧은 설명·필요 정보를 연결한다. ‘저라면’과 괄호 감상으로 정보 나열을 후기처럼 만드는 방식은 중단한다. 사람다운 말투는 선택·행동·작은 불편·반응에서 만든다.
- 의미 단위로 1~2문장/2~3줄을 묶고 빈 문단을 넣는다. 모든 소주제 바로 아래 관련 사진, 비교 정보는 짧은 표, 긴 절에는 역할이 다른 추가 사진 또는 적절한 스티커. 표의 숫자는 재열거하지 않는다.
- 확인되지 않은 내용과 조사 과정은 공개 원고에서 삭제한다. 개화는 실제 방문·촬영 날짜와 상태를 확인했을 때만 짧게 쓴다. 경험이 없으면 검증한 장면·동선·선택 기준을 쓰며 실제 방문·재방문·피로·맛을 만들지 않는다.
- 감정 괄호 총 2~3개. ㅎㅎ·ㅠㅠ·…는 해당 장면의 이유에 붙이며 동일한 도입·주차 감상·사진 감상·마무리를 반복하지 않는다. 솔직한 추천과 불편도 근거가 있는 내용에 한정한다.
- 축제·여행의 목적은 방문할 이유와 도움이 되는 선택, CPA는 확인된 혜택·가격 이득과 예약 행동이다. 생성 이미지는 간결하게 표시하고 공식 안내가 필요한 정보를 분위기 사진으로 대신하지 않는다. 별도 썸네일 배경과 후킹 문구를 빠뜨리지 않는다.

이 절과 연결 문서가 아래의 과거 표본·예시보다 우선한다. 글꼴·색·스티커 수를 흉내 내는 것만으로 일곱 블로그 분석을 적용했다고 판단하지 않는다.

## 연예 홈피드와 프로필 추가 기준

연예 글은 [연예 블로그 분석](entertainment-blog-analysis.md)을 함께 읽는다. 임씨·찌롱·집구석 언니와 어드바이저 반복 등장 블로그를 포함한 36개 블로그 대표 글 62편의 관찰이며 여행 구성을 그대로 옮기지 않는다. 검색 유입 게시물의 순서는 실제 홈피드 노출 성과가 아니며 제목 반복 빈도도 검색량이 아니다.

- 홈피드: 최신 사건이나 장면의 결과를 일찍 설명하고 근거 장면→이전 흐름→현재 입장으로 전개한다. 작성자의 짧은 생각은 확인된 사실 뒤에 붙인다.
- 프로필: 최근 방송·작품 등 관심 계기→기본 정보→활동 과정·대표 배역→현재 근황. 집구석 언니의 이야기형 프로필을 참고한다. 제목은 인물명·프로필에 국적·대표작 등 한 단계 좁은 검색어를 자연스럽게 붙인다. 항목을 채우려고 학력·가족·키 등을 만들지 않는다.
- 다예의 짧은 해요체·줄바꿈·괄호 생각, 검정 16px 나눔바른고딕 가운데·19px 번호 선 인용구·선택적 볼드가 우선이다. 분홍은 핵심 변화·대표작, 노랑은 공식 발언 요지·중요 시점, 연두는 인물 정체·활동 단계. 빨강은 실제 가격이 있는 정보에만 쓰며 모든 연예 글에 강제하지 않는다.
- 각 소주제의 이미지는 공식 방송·소속사·본인 발표 등과 대응시키고 타인의 블로그 사진을 복제하지 않는다. 실제 발언·데이트·투병의 가짜 현장 사진을 만들지 않는다. 스티커와 감정은 사건의 성격에 맞추며 투병·사망 글은 차분하게 쓴다.
- 사망설·열애·질병·갈등 원인은 공식 발표와 확인 범위를 구분한다. 본인 경험은 제공받은 사실만 사용한다. 나이와 현재 활동은 새 원고 시점에 다시 확인한다.
- 요청받은 원고는 사진·서식 적용 후 임시저장하고 발행은 별도 요청에 따른다. 썸네일 배경은 본문과 별도로 전달하며 2차 후킹 문구도 본문에서 확인되는 내용에 한정한다.

이번 추가는 분석과 기준 저장이며 네이버 원고를 수정하거나 발행하지 않았다.

- 2026-10-06 간월재 사용자 수정본 추가 교정: 확인하지 못한 정보는 공개 원고에서 뺀다. ‘당일 개화율은 확인하지 못했어요’, ‘올해 절정 날짜는 정해지지 않았어요’, ‘지금 만개라고 단정하지 않을게요’처럼 내용 없는 미확인 설명으로 소주제를 채우지 않는다. 개화 상태는 실제 날짜와 상태를 확인했을 때만 함께 쓰며, 확인되지 않으면 해당 설명·항목을 삭제한다. 필요한 추가 확인 사항은 내부 메모로만 남긴다. 이 기준은 이전 문서의 미확인 상태·조회일 공개 권고보다 우선한다.
- 뻔한 준비 조언과 가상 감상을 분량 채우기로 반복하지 않는다. 거리·요금·출발 지점·노선·프로그램·사진 포인트처럼 그 장소에서 실제 선택에 도움이 되는 확인된 내용을 우선한다. 표의 수치를 본문에 모두 재열거하지 않고 핵심 의미만 설명한다. ‘저라면’, ‘확인해주세요’, 괄호+ㅎㅎ를 문단마다 붙이지 않는다. 감상은 장면에 맞을 때만 쓴다. 사용자 수정본의 ‘땅만 보면서 올라가고 싶진 않으니까요’는 산행 맥락에 맞는 반응이며 다른 장소에 그대로 복제하지 않는다.

- 썸네일: 앞으로 사용자가 완성 썸네일 사진을 제공하고 AI는 필요시 후킹 멘트를 추천한다. 이전에 제공한 사용자 썸네일 목록의 작은 라벨+짧은 흰색 굵은 2~3줄 문구, 풍경/인물 중심 구성을 참고한다. 현재 카시아 썸네일의 실제 삽입 문구는 전체 판독을 완료하지 못했으므로 임의로 기록하지 않는다. 과장된 최저가·없는 혜택·직접 경험을 만들어 후킹하지 않는다.
- 직접 작성 요청: 사용자가 로그인한 네이버 글쓰기 창을 열고 해당 창에 작성을 요청하면 본문·번호 소주제·색·볼드·표·실제 사진 업로드·링크·가능한 스티커·사용자 썸네일 배치까지 편집한다. 현재는 도구가 보이는 것을 확인한 단계로, 모든 편집 동작이 성공한다고 미리 보장하지 않는다. 실제 작업 때 한 절씩 입력 후 화면을 확인하고 실패한 요소를 구체적으로 알린다. 기본 마무리는 검토 가능한 초안/임시저장이며 발행은 별도 요청을 따른다. 이번 스타일 분석 요청만으로 기존 글을 덮어쓰지 않는다.
- CPA 글의 목적: 예약페이지 클릭을 유도한다. 혜택·설레는 사용 장면·선택 이유·확인하고 싶은 가격을 앞세우며, 상세 제한을 장황하게 나열하거나 단점 중심의 별도 안내를 자동으로 추가하지 않는다. 식음 크레딧 등은 확인된 사용 혜택으로 소개하고 상세 사용처·제외 조건은 예약페이지로 안내한다. 실제 포함되지 않은 조식 등을 포함 혜택으로 암시하지 않는다.
- 가격 표현: 추가 요금까지 같은 조건으로 계산하여 실제 이득이 확인되면 ‘따로 추가하는 것보다 이 구성이 이득이에요!!’처럼 분명하고 생동감 있게 쓴다. ‘저라면 이 구성부터 볼 것 같아요(수영장까지 챙기면 더 끌리죠ㅎㅎ)’처럼 짧은 생각·감정을 구체적인 선택 이유와 연결한다. 확인되지 않은 할인·가격 우열·체험은 만들지 않는다.
- 발행 전 점검: 사진·색 강조·링크 목적지·가격과 포함 혜택의 표현이 맞는지 내부에서 확인하고, 본문은 읽기 쉽게 정리한다.

### 글 종류별 적용 — CPA·축제·여행 홈피드·공연 전시

- 추가 조사 완료: 기존 일곱 블로그에 현(h_ana_24)·미동(joolp00)을 더해 축제·여행 이야기·예약형·공연 전시 22편을 추가 검토했다. [장르별 분석](blog-genre-analysis.md)의 블로그별 차이·네 가지 전개를 적용한다. 공연·전시는 미동만 참고한다. 케넨·바나나푸딩 축제 표본 일부는 과거 글이므로 현재 일정에 사용하지 않는다. 실제 홈피드 노출·전환 성과·미동 좌석별 시야 비교는 검증하지 않았다.
- 같은 채팅에서 모두 작업할 수 있다. 새 채팅은 주제 정리가 필요할 때 선택하며, 같은 프로젝트의 이 기준을 읽도록 요청하면 공통 스타일을 참고할 수 있다. 다른 채팅이 이전 대화 전체를 자동으로 알고 있다고 가정하지 않는다.
- 공통: 다예의 말투·짧은 소주제·괄호 생각·가독성·색과 볼드·사진 배치·썸네일 후킹 기준을 유지한다. 검색 노출·홈피드 선정·전환 결과를 보장하지 않는다.
- CPA 상품글: 가격 메리트·단독 혜택·쿠폰·선택 이유와 자연스러운 예약 링크 중심.
- 축제 정보글: 가고 싶은 장면·핵심 볼거리·일정·위치·동선·주차 등 방문 판단 중심. 현재 일정은 공식 자료로 확인한다.
- 여행 홈피드글: 사실에 맞는 궁금증을 만드는 제목·첫 문장, 사진과 발견의 흐름·감정·구체적인 여행 장면 중심. CPA의 반복 예약 링크 구성을 그대로 적용하지 않는다.
- 공연·전시글: 작품/공연의 매력·누구에게 맞는지·일정·예매·관람 팁 중심. 관람 경험은 사용자 제공 사실만 쓰며 현재 정보를 확인한다.
- 새 유형은 사용자의 기존 글이나 수정본을 받으면 그 유형의 제목·전개·마무리 기준을 더 정교하게 보완한다. 주제와 글의 목적을 받으면 해당 유형으로 작성한다.

주제와 자료를 받으면 완성 원고, 제목 후보, 사진 순서·캡션·역할, 숙소 가격 비교표, 네이버 편집 안내를 함께 작성한다. 편집 안내에는 글씨 크기·색·볼드·밑줄·형광펜·소제목·스티커·표·링크·영상 위치를 지정한다. 분석 자료를 참고하되 다른 작성자의 문장·경험·사진을 그대로 복제하지 않는다.

## 실제 객실·시설 사진

사용자 사진과 공식/예약 사이트의 실제 사진을 조사한다. 검색한 사진은 출처와 사용할 수 있는 범위를 확인하고 객실명·침대·전망·시설·촬영/게시 시점 정보를 대조한다. 링크 카드 썸네일·쿠폰 화면·다른 객실 사진을 실제 이용 객실 사진으로 혼동하지 않는다. 사진만으로 넓이·조식 포함·시설 이용권을 확정하지 않는다. 생성 이미지를 실제 숙소 사진처럼 제공하지 않는다. 제공 가능한 사진은 원고 배치와 캡션까지 연결하고, 사용 가능 여부를 확인하지 못한 자료는 출처 확인용 링크로 구분한다.

## 사용자 제공 예약 사이트 비교

체크인/아웃·박수·성인/아이와 나이·객실 수를 맞춘다. 객실명·침대·전망·조식·환불/취소 마감·세금·추가 인원 비용·통화·쿠폰·결제 할인 적용 단계·확인 시점을 표시한다. 조건이 다른 상품은 별도로 비교한다. 기본 표시가와 결제 최종가를 구분하고 실제 확인하지 못한 회원가를 만들지 않는다. 매진·할인률·최저가 주장은 확인한 날짜와 조건에 한정한다. 룸온리+현장 조식 합계와 조식 포함 패키지 합계를 함께 계산한다. 링크를 제공하는 작업이며 별도 요청 없이 예약·결제를 실행하지 않는다.

## 사용자 제공 경험과 후기

다예의 직접 경험, 다른 작성자의 후기, 공식 정보, 조사와 추천 의견을 구분한다. 방문·숙박 시점과 현재 예약 가격의 시점을 분리한다. 사용자가 주지 않은 방문 장면과 감각을 임의로 만들지 않는다. 제3자 후기는 요약해 참고 정보로 활용하고 본인의 경험처럼 바꾸지 않는다.

## 이후 블로그 분석에서 추가로 볼 것

사진의 역할·순서·객실 유형과 설명의 대응, 공간/서비스/감각을 풀어내는 구체성, 가격 비교의 조건·시점·누락 항목·계산, 환불/조식/라운지 등 옵션 선택, 쿠폰과 결제 할인, 링크 문구와 연결 위치를 기존 서식 분석과 함께 기록한다. 표본의 좋은 구성과 다예 원고에서 보완할 부분을 구분한다.
