### 최신 추가 피드백 — 축제 본문과 모든 글의 이미지

- 축제 정보글은 본문만 읽어도 일정·공연·주차·셔틀을 알 수 있게 쓴다. 이미 본문에 정리한 정보에 ‘전체 일정 보기’, ‘주차·셔틀 안내 보기’ 등 클릭 유도 문구를 반복하지 않는다. 짧은 정보는 표 또는 공식 안내 이미지와 간단한 요약으로 전달한다. 공식 출처는 짧은 캡션으로 남기되 CPA 예약 링크 구성을 축제에 적용하지 않는다.
- 모든 유형의 글에서 각 소주제에 내용과 맞는 이미지를 최소 한 장 배치한다. 공식 실제 사진·포스터·안내표를 먼저 조사하고, 적합한 자료가 부족하면 생성 이미지로 보완한다. 공식 홈페이지가 이전 행사 사진을 프로그램 예시로 쓰는 경우 올해 실제 현장 사진으로 단정하지 않고 ‘공식 프로그램 참고 이미지’로 표시한다.
- 썸네일용 글씨 없는 배경도 기본 제공한다. 한눈에 매력이 보이는 대표 장면, 실제 촬영처럼 자연스러운 빛·질감·사람, 작게 보여도 알아볼 수 있는 구성을 선호한다. 사람이 들어가도 좋지만 사용자 얼굴을 임의로 만들어 본인이라고 설명하지 않는다. 글씨는 다예가 직접 넣으며 후킹 문구는 별도 추천한다. 사용자가 완성 썸네일을 주면 그 파일을 우선한다.
- 생성 이미지는 실제 숙소·축제 현장 기록으로 제시하지 않는다. 본문에 사용하는 경우 간단한 AI 생성 표시를 넣는다. 공식 정보의 가격·장소·교통·일정을 이미지로 만들거나 요약할 때도 확인된 내용만 사용한다.
- 열린 글쓰기 창의 수정 요청은 기존 초안을 직접 수정하고 임시저장한다. 사진 포함 본문과 별도 썸네일 배경을 전달하며 채팅에 원고를 중복 출력하거나 새 원고 보관 폴더를 계속 쌓지 않는다. 발행은 별도 요청에 따른다.

이 최신 추가 피드백은 아래의 이전 썸네일 제공·축제 링크 지침보다 우선한다.

- 원고를 재열람할 일이 거의 없으므로 별도 원고 이력·주제별 연구 폴더를 계속 쌓거나 원고를 GitHub에 올리지 않는다. 전달에 필요한 파일만 만들며 같은 글의 수정은 기존 전달본을 교체한다. 분석 기준과 이 선호는 유지한다.
- 최종 답변은 사진 포함 완성본 보기, 복사·수정할 원고, 실제 사진 다운로드, 사진 배치·글씨 색·볼드 안내의 네 링크를 기본으로 한다. 긴 원고를 채팅에 중복 출력하지 않는다.
- 소주제는 ‘객실’, ‘수영장’, ‘조식’, ‘할인 예약’처럼 1~3개 어절의 짧은 명사형을 기본으로 한다. 제목에 여러 장점과 조건을 나열하지 않고 설명을 첫 문장으로 옮긴다. 추가 분석 중 보류했던 카시아 수정은 디제이트립 분석 완료 후 사용자의 최종 요청에 따라 진행했다.
- 일곱 블로그의 표본에서 확인한 공통 흐름을 실제 문장에 적용한다: 여행 고민으로 도입, 가격·예약 이유를 일찍 제시, 사진과 짧은 설명을 번갈아 배치, 시설을 이용했을 때의 의미와 개인적인 선택 이유, 간결한 마무리. 정렬·글꼴·볼드·스티커 수는 작성자별로 다르므로 하나의 공통 규칙으로 만들지 않는다.
- 자연스러운 해요체, 짧은 문장·문단·충분한 줄바꿈, 괄호 속 생각, 가벼운 감정·기대·반응과 문자 이모티콘을 적당히 넣는다. 딱딱한 안내서나 긴 조건 설명을 피한다. 다예가 제공하지 않은 실제 투숙·맛·서비스 경험은 꾸미지 않는다. 조사에 대한 반응과 조건부 의견(저라면…)으로 사람다운 목소리를 만든다.
- 독자용 본문에는 가격을 확인한 날짜나 특정 비교 숙박일을 따로 적지 않는다. 프로모션 판매/투숙 기간과 시설 휴무처럼 필요한 일정은 적는다. 가격 비교는 두 사이트의 동일 숙박일·박수·객실·인원·세금·취소 조건을 실제로 맞추되, 낮은 요금 날짜를 달력에서 찾아 비교한다. 확인 범위를 넘어 전체 기간 최저가라고 단정하지 않는다.
- 본문에는 ‘같은 평일 1박·성인2·객실명·쿠폰 적용 표시가, 날짜별 변동’ 정도로 비교 기준을 간결히 남긴다. 상세 이용·취소 조건은 예약페이지에서 확인하도록 자연스럽게 연결한다. 가격 우열을 바꾸는 차이는 비교표에 필요한 만큼 반영하고, 내부 검증 기록은 독자용 원고와 분리한다.
- 모든 소주제에 관련 실제 사진을 최소 한 장 배치한다. 추가 사진을 먼저 조사하고, 적합한 실제 사진이 없을 때만 사용자 요청에 따라 참고 사진 기반의 설명용 이미지를 만든다. 생성 이미지는 실제 시설 사진과 구분한다. 사진은 객실·시설 설명과 대응시키며 장식용으로 다른 객실 사진을 붙이지 않는다.
- 스티커는 직접 삽입 대신 위치·감정·동작을 구체적으로 적는다(신나함, 행복하게 휴식, 뿌듯함, 아래를 가리키는 안내 등). 원고의 편집 메모와 별도 안내에 표시하고 발행 본문에서는 메모를 지운다. 색은 앞부분에 몰지 않고 후반의 전망·수영장·조식·가족 혜택·예약 선택에도 같은 의미 체계로 분배한다. 매 문단 색칠이 아니라 핵심 혜택과 주의사항을 구별한다.

### 다예가 직접 수정한 네이버 편집본 기준 — 앞으로 우선 적용

2026-10-06 사용자 요청으로 열린 카시아 글쓰기 창의 본문을 끝까지 읽고 실제 텍스트·컴포넌트 서식을 확인했다. 발행 완료 여부는 확인하지 않았으며 기존 글을 수정하거나 발행하지 않았다. 제3자 블로그 서식과 이전 HTML 미리보기보다 이 사용자 편집본과 명시 선호를 우선한다.

- 제목: 지역·숙소·시설·할인 검색어를 자연스럽게 묶되 본문의 소주제는 짧게. 제목의 길이와 소주제 길이를 혼동하지 않는다.
- 본문: 나눔바른고딕 16px, 검정 #000000, 가운데 정렬, 줄 높이 28.8px(1.8). 짧은 한 문장/한 줄 단위로 끊고 문단 사이에 빈 줄. 이전 회색 본문·파랑 중심 서식을 기본으로 쓰지 않는다.
- 소주제: `1. 단독 특가`, `2. 가격 비교`, `3. 객실`처럼 번호+1~3어절. 19px 나눔바른고딕, 왼쪽 정렬, 네이버 선 형태 인용구. 명조체로 바꾸거나 제목에 긴 설명을 붙이지 않는다.
- 강조: 핵심 부분만 볼드. 본문 강조 약 40개의 strong/b 요소를 확인했지만 모든 문장을 굵게 하는 규칙은 아니다. 일반 span 계산 굵기 400과 내부 b의 700을 구분한다.
- 분홍 글자 #FF008C: 단독 특가·가격 차액·객실 전망·중요 시설명·예약 판단의 핵심. 빨강 #FF0010: 시작가·비교표의 선택 사이트 가격·선착순 조건.
- 노랑 배경 #FFF8B2: 수영장+식음 포함 혜택·판매기간·쿠폰 적용가·마지막 패키지 추천. 연두 배경 #E3FDC8: 객실 전망별 구분·패밀리 포함 인원·라운지·투숙기간. 모든 절에서 핵심만 선택하여 분배한다.
- 예약 문구: 검정 볼드+연분홍 배경 #FDD5F5. `💚 ... 특가 보기`, `>> ... 가격 확인하기 <<` 형식을 사용. 상단 주요 링크 19px, 다른 링크 본문 크기 16px. 문구별 실제 유효한 목적지를 확인한다.
- 이모지: 💚를 기본 포인트로 쓰고 :)·ㅎㅎ·짧은 괄호 생각을 자연스럽게 섞는다. 쿠폰 안내처럼 행동이 필요한 곳에 `먼저 받아두세요!!` 정도의 활기를 주되 글 전체에 느낌표를 반복하지 않는다.
- 비교표: 3열, 가격은 약 13px, 머리글·가격 볼드, 선택 사이트의 가격 빨강. 마지막 행에 `예약 사이트`와 각 사이트별 `🔗 예약하기` 링크를 넣는다. 표 아래 조건은 11px 회색 #777777로 짧게, 무료 취소 같은 선택 포인트는 본문 크기 분홍으로 구분한다.
- 사진: 사용자가 만든 썸네일을 대표 이미지로 앞에 놓고, 이후 주제별 실제 사진과 짧은 설명을 연결한다. 쿠폰 이미지 아래 `쿠폰 받기 (이미지 클릭!)`처럼 행동 캡션을 사용할 수 있다. 캡션은 약 13px 회색 #555555. 사진 수·스티커 수를 이번 글과 똑같이 고정하지 않는다.
- 스티커: 상단 실제 관계에 맞는 제휴 고지, 도입·가격 비교·객실/시설 전환·마무리에 감정/안내 스티커. 사용자가 직접 넣는 경우 위치와 표정을 안내한다. 직접 편집을 요청받은 경우 보유 스티커 중 맞는 것을 선택할 수 있으면 삽입한다.
- 썸네일: 앞으로 사용자가 완성 썸네일 사진을 제공하고 AI는 필요시 후킹 멘트를 추천한다. 이전에 제공한 사용자 썸네일 목록의 작은 라벨+짧은 흰색 굵은 2~3줄 문구, 풍경/인물 중심 구성을 참고한다. 현재 카시아 썸네일의 실제 삽입 문구는 전체 판독을 완료하지 못했으므로 임의로 기록하지 않는다. 과장된 최저가·없는 혜택·직접 경험을 만들어 후킹하지 않는다.
- 직접 작성 요청: 사용자가 로그인한 네이버 글쓰기 창을 열고 해당 창에 작성을 요청하면 본문·번호 소주제·색·볼드·표·실제 사진 업로드·링크·가능한 스티커·사용자 썸네일 배치까지 편집한다. 현재는 도구가 보이는 것을 확인한 단계로, 모든 편집 동작이 성공한다고 미리 보장하지 않는다. 실제 작업 때 한 절씩 입력 후 화면을 확인하고 실패한 요소를 구체적으로 알린다. 기본 마무리는 검토 가능한 초안/임시저장이며 발행은 별도 요청을 따른다. 이번 스타일 분석 요청만으로 기존 글을 덮어쓰지 않는다.
- CPA 글의 목적: 예약페이지 클릭을 유도한다. 혜택·설레는 사용 장면·선택 이유·확인하고 싶은 가격을 앞세우며, 상세 제한을 장황하게 나열하거나 단점 중심의 별도 안내를 자동으로 추가하지 않는다. 식음 크레딧 등은 확인된 사용 혜택으로 소개하고 상세 사용처·제외 조건은 예약페이지로 안내한다. 실제 포함되지 않은 조식 등을 포함 혜택으로 암시하지 않는다.
- 가격 표현: 추가 요금까지 같은 조건으로 계산하여 실제 이득이 확인되면 ‘따로 추가하는 것보다 이 구성이 이득이에요!!’처럼 분명하고 생동감 있게 쓴다. ‘저라면 이 구성부터 볼 것 같아요(수영장까지 챙기면 더 끌리죠ㅎㅎ)’처럼 짧은 생각·감정을 구체적인 선택 이유와 연결한다. 확인되지 않은 할인·가격 우열·체험은 만들지 않는다.
- 발행 전 점검: 사진·색 강조·링크 목적지·가격과 포함 혜택의 표현이 맞는지 내부에서 확인하고, 본문은 읽기 쉽게 정리한다.

### 글 종류별 적용 — CPA·축제·여행 홈피드·공연 전시

- 추가 조사 완료: 기존 일곱 블로그에 현(h_ana_24)·미동(joolp00)을 더해 축제·여행 이야기·예약형·공연 전시 22편을 추가 검토했다. [장르별 분석](blog-genre-analysis.md)의 블로그별 차이·네 가지 전개를 적용한다. 공연·전시는 미동만 참고한다. 케넨·바나나푸딩 축제 표본 일부는 과거 글이므로 현재 일정에 사용하지 않는다. 실제 홈피드 노출·전환 성과·미동 좌석별 시야 비교는 검증하지 않았다.
- 같은 채팅에서 모두 작업할 수 있다. 새 채팅은 주제 정리가 필요할 때 선택하며, 같은 프로젝트의 이 기준을 읽도록 요청하면 공통 스타일을 참고할 수 있다. 다른 채팅이 이전 대화 전체를 자동으로 알고 있다고 가정하지 않는다.
- 공통: 다예의 말투·짧은 소주제·괄호 생각·가독성·색과 볼드·사진 배치·썸네일 후킹 기준을 유지한다. 검색 노출·홈피드 선정·전환 결과를 보장하지 않는다.
- CPA 상품글: 가격 메리트·단독 혜택·쿠폰·선택 이유와 자연스러운 예약 링크 중심.
- 축제 정보글: 가고 싶은 장면·핵심 볼거리·일정·위치·동선·주차 등 방문 판단 중심. 현재 일정은 공식 자료로 확인한다.
- 여행 홈피드글: 사실에 맞는 궁금증을 만드는 제목·첫 문장, 사진과 발견의 흐름·감정·구체적인 여행 장면 중심. CPA의 반복 예약 링크 구성을 그대로 적용하지 않는다.
- 공연·전시글: 작품/공연의 매력·누구에게 맞는지·일정·예매·관람 팁 중심. 관람 경험은 사용자 제공 사실만 쓰며 현재 정보를 확인한다.
- 새 유형은 사용자의 기존 글이나 수정본을 받으면 그 유형의 제목·전개·마무리 기준을 더 정교하게 보완한다. 주제와 글의 목적을 받으면 해당 유형으로 작성한다.

주제와 자료를 받으면 완성 원고, 제목 후보, 사진 순서·캡션·역할, 숙소 가격 비교표, 네이버 편집 안내를 함께 작성한다. 편집 안내에는 글씨 크기·색·볼드·밑줄·형광펜·소제목·스티커·표·링크·영상 위치를 지정한다. 분석 자료를 참고하되 다른 작성자의 문장·경험·사진을 그대로 복제하지 않는다.

## 실제 객실·시설 사진

사용자 사진과 공식/예약 사이트의 실제 사진을 조사한다. 검색한 사진은 출처와 사용할 수 있는 범위를 확인하고 객실명·침대·전망·시설·촬영/게시 시점 정보를 대조한다. 링크 카드 썸네일·쿠폰 화면·다른 객실 사진을 실제 이용 객실 사진으로 혼동하지 않는다. 사진만으로 넓이·조식 포함·시설 이용권을 확정하지 않는다. 생성 이미지를 실제 숙소 사진처럼 제공하지 않는다. 제공 가능한 사진은 원고 배치와 캡션까지 연결하고, 사용 가능 여부를 확인하지 못한 자료는 출처 확인용 링크로 구분한다.

## 사용자 제공 예약 사이트 비교

체크인/아웃·박수·성인/아이와 나이·객실 수를 맞춘다. 객실명·침대·전망·조식·환불/취소 마감·세금·추가 인원 비용·통화·쿠폰·결제 할인 적용 단계·확인 시점을 표시한다. 조건이 다른 상품은 별도로 비교한다. 기본 표시가와 결제 최종가를 구분하고 실제 확인하지 못한 회원가를 만들지 않는다. 매진·할인률·최저가 주장은 확인한 날짜와 조건에 한정한다. 룸온리+현장 조식 합계와 조식 포함 패키지 합계를 함께 계산한다. 링크를 제공하는 작업이며 별도 요청 없이 예약·결제를 실행하지 않는다.

## 사용자 제공 경험과 후기

다예의 직접 경험, 다른 작성자의 후기, 공식 정보, 조사와 추천 의견을 구분한다. 방문·숙박 시점과 현재 예약 가격의 시점을 분리한다. 사용자가 주지 않은 방문 장면과 감각을 임의로 만들지 않는다. 제3자 후기는 요약해 참고 정보로 활용하고 본인의 경험처럼 바꾸지 않는다.

## 이후 블로그 분석에서 추가로 볼 것

사진의 역할·순서·객실 유형과 설명의 대응, 공간/서비스/감각을 풀어내는 구체성, 가격 비교의 조건·시점·누락 항목·계산, 환불/조식/라운지 등 옵션 선택, 쿠폰과 결제 할인, 링크 문구와 연결 위치를 기존 서식 분석과 함께 기록한다. 표본의 좋은 구성과 다예 원고에서 보완할 부분을 구분한다.
